# Бот «Гринлайн · объекты»

Telegram-бот для прорабов, бригадиров, РП, директора и помощника. Всё, что
отправлено в бот, падает строками в Google Таблицу. План и связь с Битриксом —
`notes/0023`.

| Кнопка | Что делает | Лист таблицы |
|---|---|---|
| 📋 Отчёт за день | люди, бригада, техника и машино-часы, что сделано, проблемы, фото | «Отчёты» |
| 🧱 Заявка | тип (материал / подрядчик / техника / прочее), что и сколько, к какой дате, срочно, этап, файлы | «Заявки» |
| ✅ Приёмка | по какой заявке привезли, полностью или частично, комментарий, фото накладной | «Приёмка» (+ «Поставка» в заявке) |
| 📝 Запись по объекту | проблема / допработа / ждём от заказчика / замечание / прочее, текст, фото | «Записи» |
| 🐞 Ошибка в боте | что не так | «Ошибки» |

Отправлять данные могут прорабы, бригадиры, РП, директор и помощник.
Снабжение, экономист, бухгалтер и геодезист получают уведомления и могут
сообщить об ошибке в боте.

Отвечать голосом можно везде, кроме числа людей, техники и даты: там нужны
цифры. Голосовое сохраняется в архиве, в таблицу пишется ссылка. Уведомления:
- новая заявка и приёмка → снабжение, помощник, директор, РП объекта;
- проблема, допработа, «ждём от заказчика» → директор, помощник, РП объекта.

## Запуск за 5 минут без Google (проба)

```bash
cd bot
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # вписать BOT_TOKEN, поставить STORAGE=memory
python -m greenline_bot
```

В режиме `memory` любой, кто напишет боту, становится директором. Объекта
два, оба демо. После перезапуска всё стирается. Режим только для того, чтобы
потыкать кнопки.

## Боевой запуск

### 1. Бот в Telegram (директор, 5 минут)

1. Написать [@BotFather](https://t.me/BotFather) → `/newbot` → имя, например
   «Гринлайн объекты» → получить **токен**.
2. Там же: `/setcommands` → вставить:
   ```
   start - Главное меню
   cancel - Отменить
   bug - Сообщить об ошибке
   myid - Мой Telegram ID
   help - Что умеет бот
   ```

### 2. Google Таблица и ключ (помощник, 15 минут)

Сначала скопировать `.env.example` в `.env` и вписать `BOT_TOKEN` из шага 1
и `STORAGE=sheets`. Остальное допишем по ходу.

1. Создать пустую Google Таблицу, например «Гринлайн · бот». ID таблицы — часть
   адреса между `/d/` и `/edit`. Вписать его в `.env` → `SHEET_ID`.
2. [console.cloud.google.com](https://console.cloud.google.com) → создать
   проект → **APIs & Services → Library** → включить **Google Sheets API**.
3. **IAM & Admin → Service Accounts → Create** → любое имя → **Keys → Add key →
   JSON**. Скачается файл-ключ. Положить его в `bot/secrets/service-account.json`
   (в `.env` уже указано `GOOGLE_CREDENTIALS=secrets/service-account.json`).
   В git он не попадёт.
4. Скопировать e-mail сервисного аккаунта (`…@….iam.gserviceaccount.com`).
   В таблице нажать **Настройки доступа** и дать этому адресу роль **Редактор**.
5. Создать листы: `python -m greenline_bot.setup_sheet` (из папки `bot/`, после
   `pip install -r requirements.txt`). Через Docker:
   `docker compose run --rm bot python -m greenline_bot.setup_sheet`.
   Скрипт создаст 7 листов с заголовками; уже существующие листы он не трогает.

### 3. Архив фото (директор, 3 минуты)

1. Создать в Telegram **закрытый канал** «Гринлайн · архив». Канал, а не
   группа: у канала ID постоянный и ссылки на сообщения всегда работают.
2. Добавить бота администратором канала с правом публиковать сообщения.
3. Запустить бота (шаг 4) и написать в канале `/chatid` — бот ответит числом
   вида `-100…`. Вписать в `.env` → `ARCHIVE_CHAT_ID` и перезапустить бота.
4. Подписать на канал тех, кто должен открывать фото по ссылкам из таблицы:
   директора, помощника, РП.

Без архива бот тоже работает, но в таблице вместо ссылок на фото будут только
`file_id`. Если архив перестанет принимать фото, бот раз в час пишет об этом
админам из `ADMIN_IDS`.

### 4. Настройки и запуск

В `bot/.env` к этому моменту должны быть `BOT_TOKEN`, `STORAGE=sheets`,
`SHEET_ID`, `GOOGLE_CREDENTIALS`. Добавить `ADMIN_IDS` — Telegram ID директора
и помощника через запятую (свой ID — команда `/myid` в боте).
`ARCHIVE_CHAT_ID` — после шага 3.

На сервере с Docker:

```bash
cd bot && docker compose up -d --build     # логи: docker compose logs -f
```

Без Docker: `python -m greenline_bot`, держать запущенным через systemd или
`screen`. Бот работает через long polling: ему нужен только исходящий
интернет, белый IP и домен не нужны.

## Как помощнику вести таблицу

**Лист «Объекты»:** одна строка на объект.
- `ID` — короткий и постоянный: `О-01`, `О-02`…
- `Активен`: «да», или пусто, или «нет». С «нет» объект пропадает из кнопок.
- `Битрикс ID` — пока пусто; позже сюда впишем ID сделки.

**Лист «Пользователи»:** человек пишет боту `/start` и сам появляется в
листе с «Активен = нет», а админам приходит уведомление. Дальше помощник
заполняет три колонки:

| Колонка | Что писать |
|---|---|
| Роль | прораб · бригадир · рп · директор · помощник · снабжение · экономист · бухгалтер · геодезист |
| Объекты | ID через запятую: `О-01, О-03`. Или `все` |
| Активен | да |

На одном объекте может быть несколько прорабов, и у одного прораба или РП —
несколько объектов: просто перечислить ID. Директор, помощник, снабжение,
экономист и бухгалтер видят все объекты всегда. Изменения бот подхватывает в
течение минуты.

**Колонки «Статус» и «Комментарий офиса» в «Заявках»** правит офис руками,
бот их не перезаписывает. Статусы — как стадии в Битриксе: «Новая», «На
согласовании», «К оплате», «Частично оплачено», «Оплачено», «Закрыто»,
«Отклонено». Заявки со статусом **«Закрыто»** или **«Отклонено»** (писать
точно так) и с поставкой «получено» пропадают из списка при приёмке. Колонку
«Поставка» меняет бот, когда прораб отмечает приёмку.

Можно: добавлять свои колонки в любом месте, фильтры, цвета, листы со
сводными таблицами — бот пишет по заголовкам. Нельзя: переименовывать или
удалять колонки бота и удалять строки. Если колонку переименовать, бот
перестанет сохранять в этот лист и скажет «таблица недоступна».

Даты бот пишет как `2026-10-12` — так они правильно сортируются.

## Разработка

```bash
cd bot && python -m unittest discover -s tests -t .
```

- `domain.py` — роли, доступ к объектам, разбор чисел, техники и дат;
- `storage.py` — схема листов, Google Таблица и хранилище в памяти;
- `handlers.py` — сценарии диалогов;
- `tests/test_flows.py` — сквозные сценарии через настоящий Dispatcher с
  подменённым Telegram API: двойное «Сохранить», старые кнопки, повтор после
  сбоя связи, права ролей.

Ограничения первой версии:
- состояние диалога хранится в памяти: если перезапустить бота посреди
  заполнения, заполнение начнётся заново;
- работа с настоящей Google Таблицей тестами не покрыта — проверяется на
  первом запуске;
- голосовые не расшифровываются в текст;
- офис меняет статус заявки в таблице, но бот об этом прорабу не сообщает
  (этап 3 в `notes/0023`).
