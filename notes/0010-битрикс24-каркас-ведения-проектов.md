## 1. Схема

```
  ОБЪЕКТ (сделка CRM): договор · порядок КС · удержание · БГ · бюджет
      │
      ├── ПЛАН-ГРАФИК (проект, Гант): этапы, параллельные тоже
      │         │
      │         ├──► ЗАЯВКИ        — деньги уходят  (бригадир подаёт по ссылке)
      │         └──► ПОСТУПЛЕНИЯ   — деньги приходят (КС, аванс, возвраты)
      │
      └── СВОДКА (пятница) → ПЛАНЁРКА (понедельник)
```

## 2. Объект — сделка в CRM

**Стадии:**

| # | Стадия | Что значит |
|---|---|---|
| 1 | Договор | подписан, заполнены условия |
| 2 | Подготовка | делаем график и заявки |
| 3 | Работы | **ворота 1:** есть график и заявки на первые 2 этапа |
| 4 | Сдано на объекте | работы закончены, КС ещё не все подписаны |
| 5 | Взаиморасчёты | КС подписаны, но есть неоплаченные счета — наши или нам |
| 6 | Гарантия | осталось вернуть удержание / БГ |
| 7 | Архив | **ворота 2:** нет открытых заявок и поступлений |

**Поля (16):**

| Поле | Значения |
|---|---|
| Вид работ | мост / стена / зернохранилище / ТЦ / металл / благоустройство / лестницы |
| Материалы | наши / заказчика |
| Сумма договора | ₽ |
| Срок окончания по договору | дата |
| Прогноз окончания | дата последнего этапа в Ганте. **Отставание = прогноз − договор** |
| Порядок КС | по этапам / помесячно / в конце |
| Аванс | ₽ |
| Гарантийное удержание | % |
| БГ / обеспечение | текст: вид, сумма, до какой даты. Напоминание — задача за 30 дней до срока |
| Бюджет: материалы, подрядчики, техника, прочее | 4 поля, ₽ |
| Оплачено / **Предстоит** / Прогноз остатка | ₽ — экономист по пятницам. Предстоит = открытые заявки по объекту; прогноз остатка = бюджет − оплачено − предстоит |

## 3. План-график — проект с Гантом

- Этапы — задачи с датами. Связь ставится, **только если этап ждёт
  предыдущий**. Без связи этапы идут параллельно (гранит ∥ опоры освещения).
- Перед сдачей — этап «Финальная уборка». Ежедневная уборка — фото в чате объекта (6а).
- Этапы ведёт РП; выполнение этапа отмечает РП по фото прораба [? — кто отмечает, обсуждаем].
- Диск: `Договор и смета` · `Исполнительная и сертификаты` · `Фото` · `КС`.
- **Шаблон:** на старте один — под пилотный объект. Правит **РП**, каждая
  правка одной строкой в описании шаблона (дата, что, почему). Идущие объекты
  правка не меняет.

## 4. Заявка на закуп — деньги уходят

**Откуда:** РП — по графику на старте объекта (план закупа). Прораб или
бригадир — веб-форма по ссылке с телефона: объект, этап, к какой дате,
комментарий (что и сколько), фото или файл. Есть плановая заявка — снабженец
уточняет её, нет — заводит новую.

**Стадии:**

| # | Стадия | Кто |
|---|---|---|
| 1 | Новая | снабженец: найти поставщика, приложить счёт |
| 2 | На согласовании | директор |
| 3 | К оплате | бухгалтер. **Постоплата ждёт здесь своей даты** |
| 4 | Частично оплачено | бухгалтер |
| 5 | Оплачено | бухгалтер |
| 6 | Закрыто | снабженец, после подтверждения приёмки прорабом: **оплачено + поставлено + сертификаты (если нужны)** |
| — | Отклонено | директор |

**Поля (10):** объект · тип (материал / подрядчик / техника / прочее) · что
нужно · к какой дате · срочно (галочка) · сумма · оплачено · **безнал /
наличные** · **поставка: нет / частично / получено** · **нужны сертификаты:
да/нет** + файлы (счёт, сертификаты, накладная, чек).

Правило: заявку с «нужны сертификаты = да» нельзя закрыть без файла.

## 5. Поступление — деньги приходят

**Типы:** аванс · КС · возврат (удержания или обеспечения).

Создаёт **РП** на старте по полю «Порядок КС»: по одному на этап, на месяц или
одно итоговое. Плюс одно «Возврат удержания», если удержание есть.

**Стадии:** Запланировано → Передано заказчику → Подписано → Оплачено.

**Поля (5):** объект · сумма КС · удержание · к получению · плановая дата денег.

Стадии «Передано заказчику» и «Подписано» ведёт экономист (готовит КС),
«Оплачено» — бухгалтер.

## 6. Роли

Роль не обязательно отдельный человек, но в системе роли разведены сразу.

| Роль | Что делает в Битриксе | Сейчас |

| Руководитель проекта (РП) | ведёт объект: график из шаблона, план закупа по этапам, поступления по порядку КС, прогноз окончания, отметка этапов; правит шаблоны | **нет** [?] |
| Снабженец | заявки на закуп: поставщик, счёт, доставка, сертификаты, закрытие | **нет** [?] |
| Экономист | заводит объект после договора: условия, бюджет из сметы; готовит КС; проверяет сводку | есть |
| Бухгалтер | оплаты заявок, «Оплачено» у поступлений, обмен с 1С | есть |
| Геодезист | свои этапы: разбивка, исполнительные схемы | есть |
| Прораб | ежедневные фото в чат объекта, заявки с объекта, подтверждение приёмки | **нет** [?] |
| Бригадир | только веб-форма, без доступа в Битрикс | подрядчик |
| Администратор Битрикса | настройка полей, стадий, форм, прав | **нет** [?] |

Открытые вопросы по ролям — `0007` H7–H9. Мест в Битриксе нужно 7 (без
бригадиров); на базовом тарифе, по найденным описаниям, 5 [?].

## 6а. Чат объекта — ежедневный фотоотчёт

- У каждого проекта в Битриксе свой чат; участники — директор, РП, прораб.
- Прораб каждый день до 19:00 — фото работ и чистой площадки.
- Из сообщения создаётся задача с ответственным и сроком.
- Ежедневную уборку в систему отдельно не заводим — видно по фото.
- Заменяет переписку в разных мессенджерах.

## 7. Ритм — кто делает, кто проверяет

| Когда | Делает | Что | Проверяет |
|---|---|---|---|
| Старт объекта | РП | график из шаблона, заявки на закуп по этапам, поступления по порядку КС, PDF базового графика | директор утверждает |
| Каждый день | прораб | фото работ и чистой площадки в чат объекта до 19:00 | РП |
| Сдвиг сроков | РП | новый прогноз окончания в карточке | директор |
| Понедельник | РП | планёрка письменно в чате; **формат обсуждаем отдельно** | директор |
| Пятница | экономист | сводка директору | директор |

**Сводка (4 блока):**

| Блок | Откуда |
|---|---|
| Остаток бюджета | поля объекта: оплачено, предстоит, прогноз остатка |
| План-график | прогноз окончания против срока по договору, дней |
| Нужно денег на 2 недели | заявки стадий 1–4 по дате, безнал и наличные отдельно |
| Придёт денег за 4 недели | поступления стадий 1–3 по плановой дате |

**Автоматически ли:** шаг 1 — сохранённые фильтры с итогами считаются сами,
экономист сверяет и отправляет; шаг 2 — после обмена с 1С оплаты приходят
сами, все блоки собираются в одном отчёте (скорее всего BI-конструктор) [?],
экономист только проверяет.

## 8. 1С и тариф

- **1С:** на старте без связи — бухгалтер отмечает оплаты вручную. Обмен —
  после обкатки, на тарифе, где он есть [?].
- **Тариф:** бесплатного не хватит: там ограничены роботы и нет интеграций

## Позже, если заболит

Не настраиваем, пока нет конкретного случая. Если случай был — добавляем
одну вещь, а не всё сразу.

| Что | Когда добавлять |
|---|---|
| Тендеры и расчёты в воронке | когда начнём терять заявки или деньги в обеспечении заявок |
| Доп. работы без допсоглашения — отдельный учёт | первый случай, когда за доп. работы не заплатили |
| Замечания заказчика — отдельный реестр со сроками | ещё один штраф за замечание, которое было известно заранее |
| Реестр БГ вместо строки в объекте | больше 2 гарантий на одном объекте |
| Робот «срочно», робот-задача директору | директор пропускает заявки на согласовании |
| Шаблоны «Каркас» и «Благоустройство» | когда пойдёт объект этого вида |
| Зачёт аванса по каждому КС | когда кассовый прогноз разойдётся с фактом из-за аванса |
| Отчёт по давальческим материалам | первый объект, где заказчик его требует (`0007` H6) |
| Реестр договоров подряда | больше 3–4 платежей одному подрядчику на объект |
