# company_greenline — база знаний и рабочая обвязка

Репозиторий-накопитель строительной компании (Новосибирск). Здесь живут:
решения и их обоснования, шаблоны рабочих промптов, модели расчётов и
накопительные файлы, которые переживают отдельные разговоры с ИИ.

Главный принцип: **разговор исчезает, файл остаётся.** Всё, что заслуживает
повторного использования, ложится в репозиторий отдельной заметкой.

## Структура

| Папка | Что внутри |
|---|---|
| `notes/` | Заметки-ответы. Одна заметка = один законченный вопрос. Нумерация сквозная. |
| `templates/` | Шаблоны промптов и документов: заметка, проверка ЛСР по разделам, супервизор, чек-лист проекта. |
| `accumulators/` | Накопительные файлы, которые дописываются раз за разом: журнал решений, замечания по ЛСР, реестр «денег в работе». |
| `models/` | Расчёты кодом (Python, только стандартная библиотека). Арифметика считается кодом, а не «в уме». |
| `data/` | Данные для моделей. В git попадают только шаблоны `*.example.csv`; реальные `*.csv` игнорируются. |

## Быстрый старт

```bash
# посмотреть индекс заметок
cat notes/README.md

# посчитать триаж проектов на демо-данных
python3 models/cash_model.py --projects data/projects.example.csv

# то же на своих данных
cp data/projects.example.csv data/projects.csv   # заполнить своими цифрами
python3 models/cash_model.py --projects data/projects.csv
```

## Как заводить новую заметку

1. Взять `templates/заметка.md`.
2. Назвать `notes/NNNN-короткое-имя.md` — следующий свободный номер.
3. Дописать строку в `notes/README.md` (индекс).
4. Если заметка меняет решение — дописать строку в `accumulators/журнал-решений.md`.

## Правила работы с ИИ

См. `CLAUDE.md` — это «обвязка»: как декомпозировать задачу, когда считать
кодом, куда складывать память и как запускать второй проход-супервизор.
