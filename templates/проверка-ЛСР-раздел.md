# Промпт: проверка одного раздела сметы

**Один раздел — один заход — чистый контекст.** Не «проверь смету», а
«земляные работы», отдельно «труба», отдельно «укрепление откосов».

Признак того, что раздел взят слишком крупным: в ответе появляются общие
формулировки («в целом корректно», «требует уточнения») вместо конкретных
позиций с шифрами и цифрами. Если увидели такое — режьте раздел мельче и
заходите заново.

---

## Шаг 1. Вытащить позиции в таблицу

```
Вот раздел «<название>» из ЛСР <шифр, объект>.

Вытащи ВСЕ позиции раздела в таблицу с колонками:
шифр | наименование | ед. изм. | объём | расценка | сумма

Требования:
- Ничего не пропускать и ничего не додумывать.
- Позиции, где что-то не читается, — строкой с пометкой «не читается»,
  не выбрасывать.
- Не считать и не комментировать на этом шаге. Только извлечение.
```

## Шаг 2. Посчитать кодом

```
Возьми таблицу из предыдущего шага и посчитай Python-скриптом:
1. сумма = объём × расценка построчно; расхождения с указанной суммой;
2. итог по разделу против итога в ЛСР;
3. накладные и сметная прибыль — проверить базу начисления;
4. коэффициенты (зимние, стеснённость, индексы) — где применены, где нет;
5. дубли: одинаковые работы под разными шифрами.

Скрипт положи в models/, вывод — таблицей расхождений с суммой в рублях.
Не рассуждай об арифметике — считай.
```

## Шаг 3. Сверить объёмы с ведомостью

```
Вот ведомость объёмов работ / чертежи по этому разделу.
Сверь объёмы из таблицы с ведомостью.

Ответ — таблицей: шифр | объём в ЛСР | объём в ведомости | разница | руб.
Объёмы, которых нет в ведомости, помечай «источник не найден» —
это отдельная находка, а не мелочь.
```

## Шаг 4. Записать в накопитель

Результат раздела дописывается в `accumulators/замечания-по-ЛСР.md`.
В следующий раздел заходим **с этим файлом, а не со всей перепиской**.

## Шаг 5. Супервизор

`templates/промпт-супервизор.md`, отдельным запросом, чистый контекст.
До этого раздел считается непроверенным.
