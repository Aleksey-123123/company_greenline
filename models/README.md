# models — расчёты кодом

Правило из `CLAUDE.md`: арифметика считается кодом, а не рассуждением.
Скрипт либо сходится, либо падает с ошибкой — это проверяемо. Расчёт «в уме»
выглядит одинаково и когда верен, и когда нет.

Всё на стандартной библиотеке Python 3, без установки зависимостей.

---

## `cash_model.py` — триаж проектов

Отвечает на вопрос по каждому проекту: он **даёт** свободные деньги или
**связывает** их, и сколько зарабатывает каждый связанный рубль за год.

```bash
python3 models/cash_model.py --projects data/projects.example.csv
python3 models/cash_model.py --projects data/projects.csv --hurdle 0.6
```

### Колонки `data/projects.csv`

| Колонка | Смысл | Откуда берётся |
|---|---|---|
| `id` | шифр проекта | ваш |
| `name` | название объекта | ваш |
| `type` | `A` — материалы наши, `B` — материалы заказчика | договор |
| `contract_sum` | сумма контракта с учётом ДС, руб | договор + допсоглашения |
| `billed` | закрыто КС-2/КС-3 нарастающим итогом, руб | КС-3 |
| `received` | фактически получено денег, руб | банк |
| `cost_materials` | **остаток** затрат на материалы за наш счёт, руб | закупка |
| `cost_works` | **остаток** затрат на бригады, технику, ФОТ объекта, руб | план работ |
| `months_left` | месяцев до окончания работ | график |
| `retention_pct` | гарантийное удержание, % | договор |

### Что считает

- `связано ₽` = остаток затрат + дебиторка + гарантийное удержание.
  Это цена участия в проекте — сколько наших денег он держит до конца.
- `маржа ₽` = (сумма контракта − закрыто) − остаток затрат.
- `отдача/год` = маржа / связано × 12 / месяцев. **Главная метрика при
  дефиците оборотных средств:** не «сколько процентов маржи», а «сколько
  зарабатывает замороженный рубль за год».
- `hurdle` — порог отдачи. Ниже него связывать свои деньги невыгодно:
  дешевле не строить за свой счёт. Ставьте по стоимости денег для компании
  (кредит, факторинг) плюс премия за риск.

### Проверки, на которых скрипт падает

- закрыто КС больше суммы контракта → забыли учесть допсоглашение;
- получено больше, чем закрыто → это аванс, его нужно вести отдельно;
- тип `B`, но указаны затраты на материалы → противоречие в модели проекта;
- `type` не `A` и не `B`, отрицательный срок, нулевая сумма контракта.

## `collect_plan.py` — очередь взыскания

В каком порядке собирать деньги, которые **уже заработаны**. Ранжирует по
ожидаемым деньгам в неделю:

```
приоритет = сумма × вероятность / недели до денег
```

Такой порядок максимизирует деньги на счёте в ближайший месяц, а не «сумму на
бумаге»: крупный, но безнадёжный долг проигрывает трём мелким и быстрым.

```bash
python3 models/collect_plan.py --file data/receivables.example.csv
```

### Колонки `data/receivables.csv`

| Колонка | Смысл |
|---|---|
| `id` | шифр строки |
| `source` | источник (непринятые КС, допработы без ДС, удержание, обеспечение, дебиторка, неликвиды, НДС) |
| `object` | объект |
| `amount` | сумма, руб |
| `probability` | вероятность получить, 0…1 — оценка, ставится честно |
| `weeks` | недель до денег на счёте |
| `action` | конкретное действие, а не «проработать» |
| `owner` | ответственный: директор / прораб / бухгалтер / экономист / помощник |

Результат каждой итерации переносится в
`accumulators/реестр-денег-в-работе.md`.

## Демо-данные

`data/*.example.csv` — **выдуманные** цифры для проверки работоспособности
скриптов. Ни одна из них не является оценкой реального положения компании и
не должна попадать в заметки. Свои данные кладите в `data/projects.csv` и
`data/receivables.csv` — они в `.gitignore` и в репозиторий не уедут.
